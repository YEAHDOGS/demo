# Content plan — demo

How the portfolio gets its content, and in what order.

## Case-study template

Every `/work/<slug>` page follows the same skeleton so writing new ones is fast:

1. **Header** — project name, one-line pitch, live link, repo link
2. **Problem** — what itch this scratched (2–3 sentences)
3. **Build** — stack, notable engineering choices, what was hard
4. **Result** — what's live, metrics if any, what came next
5. **Media** — screenshots first; short clips second; AI-generated only as placeholder with a "replace with real" note

Keep each section tight. The whole page should read in under 2 minutes.

## Content rules

- Real screenshots beat AI images; source pictures from the actual thing first
- No "featured applicant"-style endorsement framing on anything third-party
- Mobile-viewport check on every page before it ships
- Restrained visuals: no rainbow-soup multicolor excess, no image overload
